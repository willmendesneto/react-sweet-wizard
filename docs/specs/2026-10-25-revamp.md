# Revamp: bugs, dependencies, CI, bundle, Vitest, simplification

- Status: approved
- Ticket: none (GitHub issue to be opened from this spec)
- Date: 2026-10-25
- Mode: spec-driven

## Context

`react-sweet-wizard` 2.0.1 is a stable, 200-line React library whose toolchain stopped moving in
2021 to 2023: React 16/17 dev dependencies, TypeScript 4.4, Jest 27 with Babel, ESLint 8 with a
343-line config, Rollup 2, Prettier 2, Husky 7, CircleCI, and `bundlesize` 0.18, which no longer
loads on current Node (native `iltorb` binding, see `docs/TROUBLESHOOTING.md`). `npm outdated`
lists 41 outdated packages, most of them one or more majors behind. The onboarding docs recorded
code-level debt as well: `Step` types `id` as `string` while the README and changelog promise
numbers; `goTo(number)` means index while `goTo(string)` means id; step registration in `Steps` is
count-based; `Steps` calls hooks after conditional `throw`s; `onNext` is `async` but typed `void`;
`package.json` publishes `es2015` and `es2020` fields that the build never produces; the README
claims a bundle size that does not match the budgets and documents `np` for publishing although the
scripts use `npm version`.

The maintainer asked for a revamp covering bug fixes, dependency updates, a move to GitHub Actions,
code improvements, a smaller bundle, a Jest to Vitest migration and simplification, and wants to
discuss approaches before implementation. This spec is the contract for that discussion and for the
plan that follows.

## Goal

A 3.0.0 release of `react-sweet-wizard` built, tested and released with a current toolchain
(TypeScript 5+, Vitest, ESLint 9+ flat config, Prettier 3, Rollup 4, Node 22+ for
development, GitHub Actions for CI), with the known API inconsistencies fixed and documented, every
published artefact at or below its current gzip size, the same or higher test coverage, and the same
public exports (`WizardProvider`, `Steps`, `Step`, `useWizardContext`, `DefaultWizardStepProps`).
Consumers on React 18 or later upgrade by reading one changelog section.

## Non-goals

- No new wizard features (validation framework, animations, URL sync, persistence, focus management).
- No change to the headless contract: no styles, no UI beyond the `div` per `Step`.
- No rename of public exports and no new required props.
- No monorepo, no second package, no demo app inside this repo.
- No automatic publishing from CI in this round; releases stay maintainer-driven from a local
  machine. CI may build and verify the tarball but not publish.
- No rewrite of consumer documentation beyond correcting what is wrong or outdated in `README.md`.

## Acceptance criteria

Each criterion is checkable by a test or a manual step. Criteria are grouped by workstream; the
letter is only a label, the number is the id.

### A. Bugs and API consistency

1. Given a consumer renders `<Step id={0}>` and `<Step id="b">` inside `Steps`, when
   `npm run lint:types` runs, then it passes, and `getActiveStep()` returns `{ id: 0 }` for the first
   step at runtime.
2. Withdrawn on 2026-10-25 (maintainer decision): `goTo` keeps its 2.x semantics, number = index and
   string = id, and no index-specific navigation method is added. The rule is stated explicitly in the api doc and README.
3. Given `Steps` renders three `Step` children with ids `['a', 'b', 'c']` and the parent re-renders
   with ids `['a', 'x', 'c']`, when the effect runs, then `steps` equals `[{ id: 'a' }, { id: 'x' },
   { id: 'c' }]` (registration compares ids, not only the count), and when the parent re-renders with
   identical ids, then `setSteps` is not called again.
4. Given a `WizardProvider` with no registered steps, when `useWizardContext()` is read, then
   `isFirstStep` is `true`, `isLastStep` is `false` and `getActiveStep()` returns `undefined` without
   throwing.
5. Given `onNext(cb)` is called with a callback that rejects, when the rejection happens, then the
   active step does not change and the returned promise rejects with the same error; given a callback
   that resolves, then the returned promise resolves after the step advanced. `onNext` is typed
   `(cb?: () => void | Promise<void>) => Promise<void>`.
6. Given `Steps` receives an invalid child or no children, when it renders, then it throws the same
   error messages as 2.0.1, and `npm run lint` reports no `react-hooks/rules-of-hooks` violation in
   `src/` (hooks are called before any conditional `throw`).
7. Given the published tarball (`npm pack`), when its `package.json` is inspected, then it has no
   `es2015`, `es2020`, `jsnext:main`, `cjs` or `browser` fields, has an `exports` map whose `.` entry has `import`
   and `require` branches, each with `types` first and a `default`, plus `./package.json`, and every file referenced by `main`, `module`, `types` and
   `exports` exists in the tarball.

### B. Dependencies and runtimes

8. Given a fresh clone on Node 22 and 24, when `npm ci && npm run lint && npm run lint:types &&
   npm test && npm run build && npm run size` runs, then every command exits 0 on all three versions.
9. Given `package.json`, when inspected, then `engines.node` is `>=22` (Node 20 is end of life; maintainer decision 2026-10-25), `.nvmrc` pins Node 24.22.0
   (the current LTS), `devDependencies` contain no Babel packages, no `jest*`, no `@testing-library/react-hooks`,
   no `uglify-js`, no `bundlesize`, no `coveralls`, and `npm outdated` reports no package more than one
   major behind its latest.
10. Given the library is installed in a sample app on React 18.x and 19.x (test matrix in
    CI using `npm install react@<v> react-dom@<v>` before `npm test`), when the test suite runs, then
    it passes on both, and `peerDependencies` is `react >=18.0.0` (`react-dom` dropped: never imported)
    (breaking: React 17 is no longer supported).
11. Given `npm audit --omit=dev`, when run on the tarball's dependency tree, then it reports zero
    runtime dependencies and zero vulnerabilities (the package stays dependency-free).

### C. Continuous integration on GitHub Actions

12. Given a push or pull request to `main`, when `.github/workflows/ci.yml` runs, then it executes
    lint, type check, unit tests with coverage, build and size check as separate named jobs on a Node
    matrix of 22 and 24 and a React matrix of 18 and 19 for the test job, and the
    `.circleci/` directory no longer exists.
13. Given the CI test job finishes, when coverage is reported, then it is uploaded to Coveralls
    through `coverallsapp/github-action` using the repository's `GITHUB_TOKEN` (no `COVERALLS_REPO_TOKEN`
    in the repo), and the README badges point at GitHub Actions and Coveralls on `main`.
14. Given a version tag `v*` is pushed, when `.github/workflows/release.yml` runs, then it runs the
    full gate set, `npm pack --dry-run`, and attaches the changelog section for that version to a
    GitHub Release. It does not run `npm publish`.
15. Given `.github/dependabot.yml` exists, when Dependabot evaluates the repo, then it opens grouped
    weekly PRs for npm dev dependencies and GitHub Actions, with majors in their own group.

### D. Bundle

16. Given `npm run build`, when it completes, then it produces `dist/esm/index.mjs`,
    `dist/esm/index.d.mts`, `dist/cjs/index.cjs` and `dist/cjs/index.d.cts` from one Rollup 4 configuration (the UMD build
    is removed; breaking for script-tag consumers), with source maps, and no
    Babel step.
17. Given the built artefacts, when `npm run size` (`size-limit` with the `file` preset, gzip)
    runs, then every budget passes. Budgets: 1500 B gzip for ESM and for CJS (raised by the maintainer
    on 2026-10-25 from the original 1.2/1.3 KB target to pay for reducer-side registration).
18. Given the ESM output, when imported by a bundler, then `sideEffects` is `false`, the output uses
    the automatic JSX runtime (`react/jsx-runtime`) and contains no `displayName` assignment and no
    `process.env.NODE_ENV` check.

### E. Jest to Vitest

19. Given `vitest.config.ts` with the `jsdom` environment and `@vitest/coverage-v8`, when `npm test`
    runs, then the 10 existing scenarios in `src/index.test.tsx` plus the new scenarios for criteria
    1 to 6 pass using `renderHook` and `act` from `@testing-library/react` 16, and the files
    `jest.config.js`, `jest.setup.js` and `babel.config.js` no longer exist.
20. Given the Vitest coverage report, when thresholds are evaluated, then they are at least the
    current ones (branches 91, functions 100, lines 96, statements 96) and the run fails below them.
21. Given a test asserts that a component throws, when it runs, then it uses `expect(() =>
    render(...)).toThrow(message)` with React's console error silenced for that test only, with no
    `result.error` API (removed in Testing Library 16).

### F. Simplification

22. Given `eslint.config.js` (flat config), when `npm run lint` runs on the repo, then it passes, the
    file is at most 80 lines, and it keeps `typescript-eslint`, `react`, `react-hooks`, `jsx-a11y`,
    `testing-library`, `vitest` and `prettier` as the plugin set. `sonarjs` and `unicorn` are dropped
    unless a rule from them is listed in the plan with a reason.
23. Given `package.json` scripts, when listed, then they are exactly: `build`, `lint`, `lint:fix`,
    `lint:types`, `lint:package`, `test`, `test:watch`, `test:coverage`, `size`, `prepare`, `prepack`,
    `preversion`, `version`, and `AGENTS.md` plus `docs/` reference only those names.
24. Given `src/index.tsx`, when reviewed, then the reducer, provider, components and hook are split
    into `src/context.ts`, `src/reducer.ts`, `src/WizardProvider.tsx`, `src/Steps.tsx`, `src/Step.tsx`,
    `src/useWizardContext.ts` and re-exported from `src/index.ts`, with the same five public exports
    plus the exported type `WizardContextValue<T>` (the former
    unexported `WizardStepperContextProps`).

### G. Documentation and release

25. Given `CHANGELOG.md`, when read, then `## [Unreleased]` lists every breaking change (criteria 5,
    7, 9 engines, 10 peers, 16 UMD removal) under `### Breaking`, with a one-line migration note each, and every other change
    under `### Added`, `### Changed` or `### Fixed`.
26. Given `README.md`, when read, then it shows numeric and string `Step` ids, states the `goTo` rule (number = index,
    string = id), has no unpkg or script-tag section, states the measured gzip size of the ESM build, documents `npm version`
    instead of `np`, and has no reference to CircleCI.
27. Given `docs/`, when `node check-docs-links` from the onboarding tooling runs, then it passes, and
    the files listed under Docs impact reflect the new toolchain (no mention of Jest, Babel,
    `bundlesize` or CircleCI except in `CHANGELOG.md` and the troubleshooting history).

## Rollout and risks

- **Release as 3.0.0.** Criteria 5, 7, 9, 10 and 16 are breaking for some consumers. Ship a
  `3.0.0-rc.0` from the release branch first (`npm publish --tag next`) to exercise the tag workflow
  and the tarball before `latest` moves.
- **`goTo` semantics.** Unchanged by decision; the ambiguity (number = index, string = id) stays
  and is documented explicitly.
- **Peer range.** Raised to `>=18.0.0` by decision; Testing Library 16 and the automatic JSX runtime
  target React 18+. React 17 consumers stay on 2.x.
- **Size budgets.** Splitting into files does not change the bundle, but the automatic JSX runtime
  and ES2019 output do; measure before setting budgets (criterion 17) and reject the slice if any
  artefact grows over its 2.0.1 gzip size.
- **CI secrets.** Coveralls through the GitHub action needs no repo secret; if the project is not
  linked on Coveralls, the step is marked `continue-on-error` until it is.
- **Rollback.** Each workstream is one or more slices with the gates green; a bad slice is reverted
  on the branch. A bad 3.0.0 on npm is followed by a 3.0.1 or deprecated with `npm deprecate`, never
  unpublished (see `docs/playbooks/RELEASE-WORKFLOW.md`).
- **Monitoring.** npm download split between 2.x and 3.x, GitHub issues, and the CI matrix.

## Open questions

All resolved with the maintainer on 2026-10-25:

1. `goTo(number)`: keep index semantics; no new navigation method (criterion 2 withdrawn).
2. React peer range: `>=18.0.0`; CI matrix React 18 and 19.
3. Bundler: Rollup 4.
4. UMD build: removed; ESM and CJS only.
5. TypeScript: 6.0 (one major behind the native 7.x compiler; typescript-eslint supports <6.1).
6. `isLastStep` with no steps: `false` (criterion 4).
